# SomaticVR Tracker Emulator

A C#/.NET 9.0 console application that emulates Server-compatible trackers and a Bridge Client to send SteamVR packets to the bridge. The application uses real captured data. For development, testing, and integration purposes.

## Features

### Current
- Emulates multiple trackers and a bridge client that connects to the server.
- Sends real captured data to the Server.
- Implements UDP protocol handshake and packet types
- Retry logic for server discovery

## Prerequisites
The application requires data collected by the server. It also depends on the ProtobufMessages C# class generated by that server backend.

### Data Requirement
The server can be used to capture packets coming from trackers and SteamVR devices that send data over the bridge. This data is saved to the servers AppData directory:

```
%APPDATA%\ServerBackend%\EmulationData
```
 Each of the data jsonl files contain captured *acceleration*, *rotation*, *heartbeat*, and *ping pong* packets from each of the trackers and *position* and *status* packets from each of the SteamVR devices. Below are the files created by the server backend.
- `DeviceList.jsonl` - List of MAC addresses of devices used during capture.
- `DeviceListBridge.jsonl` - Lists bridge devices. Currently only being used to see if bridge was connected during capture. 
- `ResetStanceFull.jsonl` - Captured data during full reset stance.
- `ResetStanceMounting.jsonl` - Captured data during mounting reset stance.
- `ResetStanceFootMounting.jsonl` - Captured data during a foot mounting reset stance. 
- `StayAlignedStanceChair.jsonl` - Captured data during a stay aligned chair sitting stance.
- `StayAlignedStanceFloor.jsonl` - Captured data during a stay aligned floor sitting stance.
- `RotationAccelerationData.zip` - Captured data during free movement. This data need to be unzipped. 

#### Sample Location
Sample is provided with the repo. In order to use the data unzip the zip file, then move all data to a folder named `EmulationData` in the appropriate location.

### ProtobufMessages Requirement
The project does **not** generate its own protobuf C# bindings. Instead it reuses the generated ProtobufMessages.cs file form the server backend. To make things easier for the user, the ProtobufMessages.cs file has been saved into the include directory in this project. It is not guaranteed to be up-to-date and should be replace by the ProtobufMessages.cs being used by the server backend.

### Build

```
dotnet build
```

### Run

```
dotnet run
```
