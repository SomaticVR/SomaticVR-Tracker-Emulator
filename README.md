# SomaticVR Tracker Emulator

A C#/.NET 9.0 console application that emulates Server-compatible trackers and a Bridge Client to send SteamVR packets to the bridge. The application uses real captured data. For development, testing, and integration purposes.

## Features

### Current
- Emulates multiple trackers and a bridge client that connects to the server.
- Sends real captured data to the Server.
- Implements UDP protocol handshake and packet types
- Retry logic for server discovery

## Initial Setup
Before building or running the emulator for the first time, you must prepare the required data and protobuf bindings. The emulator depends on files generated by the backend server.

```
./tools/Create-Symlinks.ps1
```

This script performs two tasks:
 1. **Creates a symlink to the Protobuf directory** from the server backend into `src/Protobuf/`
 2. **Creates a symlink to the EmulationData directory** used by the server backend so the emulator can read the captured tracker and SteamVR packets. 

After running the script once, the copied files and symlink remain in place.
You do not need to run the script again unless the backend regenerates protobuf files or new captured data is produced. 


## Prerequisites
The application requires data collected by the server. It also depends on the ProtobufMessages C# class generated by that server backend. Running the script from the Initial Setup section will fulfill both of these requirements. 

### Data Requirement
The server can be used to capture packets coming from trackers and SteamVR devices that send data over the bridge. This data is saved to the servers AppData directory. The setup script (Create-Symlinsk.ps1) automatically links the backend’s EmulationData directory into the emulator project so the application can read the captured packets.


 Each of the data jsonl files contain captured *acceleration*, *rotation*, *heartbeat*, and *ping pong* packets from each of the trackers and *position* and *status* packets from each of the SteamVR devices. Below are the files found in the EmulationData directory.

- `DeviceList.jsonl` - List of MAC addresses of devices used during capture.
- `DeviceListBridge.jsonl` - Lists bridge devices. Currently only being used to see if bridge was connected during capture. 
- `ResetStanceFull.jsonl` - Captured data during full reset stance.
- `ResetStanceMounting.jsonl` - Captured data during mounting reset stance.
- `ResetStanceFootMounting.jsonl` - Captured data during a foot mounting reset stance. 
- `StayAlignedStanceChair.jsonl` - Captured data during a stay aligned chair sitting stance.
- `StayAlignedStanceFloor.jsonl` - Captured data during a stay aligned floor sitting stance.
- `RotationAccelerationData.jsonl` - Captured data during free movement.

#### Sample Data Location
In case emulation data has not been collected yet by the server backend, sample data is provided with the repo in the SampleData directory. In order to use the data unzip the SampleData.zip, then move all data to a folder named `AppData\Roaming\SomaticVR-Server-Backend\EmulationData\`. You will also need to put the vrconfig.yaml in the `AppData\Roaming\SomaticVR-Server-Backend\` directory in order for the server to recognize the trackers. If you already have a vrconfig.yaml you may want to save it to a safe location and move it back to this directory once you are done using the emualtor. 

### ProtobufMessages Requirement
The emulator uses the same protobuf C# bindings generated by the SomaticVR backend server. These bindings are not generated by this project. Instead, the setup script (Create-Symlinsk.ps1) automatically creates a symbolic link to the `protobuf` directory into 

```
src/Protobuf/
```

This ensures the emulator uses the exact same message defintions ast he server. If the backend updates its protobuf defitions, rerunm the setup script to refresh the files. 

### Build

```
dotnet build
```

### Run

```
dotnet run
```
